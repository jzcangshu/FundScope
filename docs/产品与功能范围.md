# 私募基金估值分析看板：产品与功能范围

本文件是产品范围的唯一长期依据。它描述当前仓库实际支持的能力，不把早期草案、模拟数据或未来设想写成现成功能。

## 1. 产品定位

这是一个面向私募基金内部运营和管理层查看的估值数据系统。它接收估值表 Excel（电子表格），完成安全归档、解析、标准化、校验、符合条件时自动发布、异常人工复核、后台分析和看板查询。历史迁移支持目录盘点、清单预演和通过正式导入接口上传。

系统的唯一业务数据来源是估值表 Excel。邮件、手工上传和历史迁移只是同一类文件的不同接入方式，不是新的业务数据源。产品名称别名、份额类别、科目映射、风险规则和系统账号属于系统运行所需的人工维护配置，不能被描述为从估值表自动获得。

## 2. 当前范围状态

| 状态 | 含义 |

## 3. 用户和权限

系统包含管理员、业务员、普通看板和老板四个角色，并支持账号级产品范围。管理员始终拥有全部产品权限；其他角色默认全部产品，可在创建账号时或创建后改为指定产品。下表为全部产品账号的角色能力；指定产品账号的查看、导出、导入、复核和维护均按授权范围隔离，跨产品的全局运营功能不开放。老板额外可查看所有账号的权限清单，并修改其他非管理员账号的可见产品范围，自身产品数据仍按授权读取。详见 [产品权限说明](产品权限说明.md)。

| 能力 | 系统管理员 `admin`（管理员） | 业务员 `operator`（业务员） | 普通看板 `viewer`（只读看板） | 老板 `boss` |
|---|---:|---:|---:|---:|
| 查看公司总览、风险和产品 | 是 | 是 | 是 | 是 |
| 上传、处理和查看导入批次 | 是 | 是 | 否 | 否 |
| 复核、发布、驳回、撤回和恢复估值版本 | 是 | 是 | 否 | 否 |
| 维护产品、别名、份额类别、科目映射 | 是 | 是 | 否 | 否 |
| 维护风险规则、处理风险事件 | 是 | 是 | 风险规则可配置；风险事件只读 | 同普通看板 |
| 邮件设置查看、立即同步 | 是 | 是 | 否 | 否 |
| 更新邮箱账号、授权码、测试连接、暂停/恢复自动邮件同步 | 是 | 否 | 否 | 否 |
| 维护账号 | 是 | 否 | 否 | 否 |
| 查看账号权限一览 | 是 | 否 | 否 | 是 |
| 修改账号可见产品范围 | 是 | 否 | 否 | 可修改其他非管理员账号 |
| 修改系统设置、查看运维摘要 | 是 | 否 | 否 | 否 |

| 执行原始文件清理 | 是 | 否 | 否 | 否 |

前端导航和按钮只是体验层控制，不能作为安全边界。所有写接口和管理接口都由后端重新检查角色。

## 4. 正式页面和真实行为

正式前端路由位于 `frontend/src/app/router.tsx`。以下列表按当前实现描述页面，不包含早期模拟 Demo 的页面设想。

### 4.1 登录和初始化

- `/login`：本地账号登录。服务端使用 HttpOnly（脚本不可读取）会话 Cookie；失败只返回通用错误。
- `/initialize`：仅在数据库还没有账号时出现，创建第一个管理员并直接建立会话；初始化完成后不可重复使用。
- 用户菜单：退出登录。当前正式页面没有自助找回密码；管理员在账号管理页重置密码，用户可在当前会话中修改密码。

### 4.2 总览和产品分析

- `/dashboard`：读取公司总览、公司净值指数序列和各产品最新已发布估值。支持选择 `as_of`（估值日）刷新同日视图，展示净资产、产品覆盖、公司日收益、公司指数当前值与历史序列（含运行峰值回撤）、开放/已确认风险数、质量状态和产品摘要。
- `/risk`：读取风险事件并允许业务员或管理员填写处理状态、处理意见和证据引用。
- `/funds`：分页查看产品主数据和最新已发布数据，可按名称、产品状态和估值日查询；支持产品列表 CSV（逗号分隔文件）导出。
- `/funds/:id`：产品详情页。当前正式页签只有净值走势、持仓、净值明细和数据质量；页头读取产品详情摘要（含资产、净资产、单位/累计净值和区间收益）。
  - 净值走势：按起止日期读取已发布版本，绘制单位净值、累计单位净值和调整后净值曲线。
  - 净值明细：以表格展示单位净值、累计单位净值、累计派现、调整后净值、日收益、累计收益、分析状态和指标来源。
  - 持仓：按估值日分页读取后端返回的持仓，固定按市值降序；市场和账户可能为空。
  - 数据质量：展示当前版本的校验结果、严重度、数值和来源位置。

产品详情的资产配置、份额每日数据、完整概览、版本差异和统一来源定位目前没有页面 JSON 查询接口。资产配置和份额数据可以通过 CSV 导出接口获取，但导出接口不能被描述为页面查询接口。

### 4.3 数据运营

- `/imports`：创建手工上传批次，逐个上传 `.xls`（旧版 Excel）或 `.xlsx`（新版 Excel），完成批次后排队处理；可查看文件哈希、重复标记、后台任务状态、校验结果、重试技术失败和受控下载原始文件。历史迁移清单的生产上传由命令行工具执行，需按迁移指南先完成认证和样本验收。
- `/reviews`：分页查看指定估值版本状态的复核队列。默认是 `pending_review`（待复核），另可查看 `publishable`（可发布）版本；干净版本在导入校验完成后已自动发布，警告版本需要填写原因并明确发布，阻断版本需要先记录人工复核决定。
- `/mail`：查看邮箱非敏感设置和账号；管理员可更新账号、授权码、测试连接和暂停/恢复自动同步；管理员或业务员可立即同步并查看同步记录。

导入页面不提供重新解析、重新校验、网页目录导入、单文件删除、已知例外标记或伪造的产品识别结果。当前接口没有这些状态语义。

### 4.4 基础配置和系统管理

- `/admin/funds`：维护产品标准名称、产品代码、成立日期、可选策略/管理人/备注、别名和份额类别。策略和管理人是人工维护元数据，不是 Excel 自动识别结果。
- `/admin/subjects`：维护科目代码/前缀或名称模式、标准类别、叶子标记、是否纳入持仓、有效期、规则版本和启停状态。
- `/admin/risk-rules`：维护六种已实现风险规则类型的版本。修改不是覆盖旧记录，而是为同一规则编码创建新版本。
- `/admin/users`：管理员创建、禁用、启用、修改角色、重置密码和撤销用户全部会话。
- `/account-permissions`：老板和管理员查看账号的身份、状态、具体可见产品及最后登录时间，支持搜索、筛选、分页、刷新与修改可见产品。老板仅能看到启用账号，且隐藏用户名为 `admin`、`boss`、`operator` 的测试账号；列表、搜索和分页总数采用同一范围，老板端不显示状态筛选。管理员仍可查看和筛选停用账号，并在账号管理中重新启用；重新启用后账号恢复显示，历史记录及产品授权保留。老板不能修改自己或管理员的范围，角色与其他账号管理操作仍仅向管理员开放。
- `/admin/audit`：查询脱敏审计摘要。没有日志删除接口。
- `/admin/settings`：修改白名单系统设置；运行时是否立即生效由接口返回的说明决定。
- `/admin/retention`：查看运维摘要、执行原始文件清理预演和确认执行。清理前必须先预演，执行请求必须带固定确认短语和原因。

## 5. Excel 能力边界

### 5.1 接收和识别

当前接收 `.xls` 和 `.xlsx`。解析器不依赖固定行号，而是寻找同时包含“科目代码”和“科目名称”的表头，再按字段标签读取估值表。支持多个工作表，选择第一个能识别估值表表头的工作表。

产品识别只使用工作簿前部文本和已配置产品/别名；文件名只能形成未决候选，不能单独提升为产品身份。估值日期从工作簿前部文本解析，支持常见的年月日、斜杠、连接符和八位数字形式。

### 5.2 已标准化字段

估值汇总字段包括：

- 总资产、总负债、基金资产净值；
- 基金单位净值、累计单位净值、昨日单位净值；
- 日、周、月、季、年和累计收益率（可用时）；
- 累计派现、今日可用头寸；
- 份额类别的净资产、实收资本、单位净值、累计单位净值、昨日单位净值和日收益；
- 科目层级、数量、成本、成本占净值、市值、市值占净值、估值增值和停牌信息；
- 叶子持仓的证券代码、名称、数量、单位成本、市价、市值、净值权重、估值增值、市场和账户。

市场和账户只在 Excel 祖先科目名称明确包含相应信息时保存，字段允许为空。系统不会根据证券代码、名称或常识猜测市场和账户。

金额和比例使用十进制定点值保存。百分比单元格按百分点转成比例，例如 `2.5` 变为 `0.025`；带逗号的小数按最后一个分隔符判断常见美式/欧式写法，无法安全判断时不静默放大数值。

### 5.3 不能由当前数据准确提供的内容

以下能力不属于首期产品承诺：

- 外部基准超额收益、Alpha（阿尔法）、Beta（贝塔）、跟踪误差和信息比率；
- 行业、主题、风格暴露和证券分类穿透；
- VaR（风险价值）、CVaR（条件风险价值）和压力测试；
- 精确流动性天数、成交容量和冲击成本；
- 合同、监管或投资授权限额自动判断；
- 精确交易归因、单券收益贡献、财务级当日盈亏；
- 精确申购、赎回、分红和现金流事件。

Excel 中偶然出现的已实现收益、可分配利润或申赎余额，不能被自动命名为上述精确指标。若未来要支持这些能力，必须先批准新的数据源和口径。

## 6. 校验、分析和风险口径

### 6.1 校验

当前规则代码为：

| 规则 | 实际检查 | 阻断级别 |
|---|---|---|
| `asset_liability_balance` | 总资产 - 总负债 = 基金资产净值，默认金额容差 0.01 | 是 |
| `share_net_asset_total` | 份额净资产合计 = 基金资产净值，默认金额容差 0.01 | 是 |
| `daily_return_reconciliation` | 当前单位净值/昨日单位净值 - 1 与表内日收益一致，默认比例容差 0.000001 | 否，差异为警告 |
| `position_market_value_reconciliation` | 数量 × 市价与市值一致，使用绝对容差和相对容差的较大值 | 否，差异为警告 |
| `valuation_product_identity` | 产品身份已解析并唯一匹配 | 是 |
| `valuation_date_identity` | 估值日期已解析 | 是 |
| `parser_warning` | 记录解析器提示 | 否 |

阻断级发现使估值版本进入 `pending_review`（待复核），没有阻断级发现的版本进入 `publishable`（可发布）。导入校验同时满足无阻断级、无警告时，系统立即自动发布；只有警告的版本保留为 `publishable`，发布时需要明确确认；校验发现和来源位置随版本保存。

### 6.2 净值、收益和回撤

净值序列优先使用每个估值日均存在的累计单位净值。否则使用单位净值，并在存在累计派现时加回累计派现；缺失派现不会被当成零。序列会按估值日排序，重复日期直接拒绝。

调整后净值的日收益为：

```text
当日调整后净值 / 前一估值日调整后净值 - 1
```

累计收益以序列中第一个可用调整后净值为基准。分析服务另外按累计调整后净值计算运行峰值和回撤；产品详情 JSON 没有单独回撤序列接口，公司级回撤序列由 `dashboard/series`（公司净值与回撤序列）按公司指数提供。

产品的“今年”区间回撤优先从 1 月 1 日或此前最近估值起算；缺少年初基准时，从当年首条已有估值起算，并展示实际日期和“不代表完整区间”的提示。首个已有估值日不一定是全年第一个交易日，系统不会补造缺失净值。净值明细、产品区间回撤查询和导出采用相同规则；固定期限统计、成立以来回撤完整性要求、收益口径及历史风险事件保持原规则。

### 6.3 公司指数

公司指数从 `1.0000` 开始。除首个可计算日外，使用紧邻估值日的各产品前一日净资产作为权重，仅纳入同时有当前日记录和当前日收益的产品：

```text
公司日收益 = Σ（产品前一日净资产 / 公司前一日净资产 × 产品日收益）
公司指数 = 上一指数 ×（1 + 公司日收益）
```

某估值日若没有任何可计算的公司日收益（如全部产品收益缺失或前一日净资产不可用），该日公司指数为空值，不会把缺失当作零收益；恢复可计算后，指数从最后一个有效指数继续链接，不会因单个缺口日永久中断。

响应会返回有效产品数和覆盖信息。它不是外部市场基准，也不使用单位净值直接相加或平均。

### 6.4 资产配置和集中度

资产配置只使用活动映射标记为纳入持仓的叶子科目，并按标准类别聚合市值；导出时可选择以净资产、总资产或持仓市值作为分母。

集中度按证券代码合并跨账户持仓，计算单一证券最大绝对权重、前五大绝对权重和 HHI（赫芬达尔指数）。这只是基于估值日余额的结构指标，不是交易归因或风险模型。

### 6.5 风险规则

当前支持的规则类型只有：`daily_return`（日收益）、`max_drawdown`（最大回撤）、`current_drawdown`（当前回撤）、`single_position_weight`（单票权重）、`top_five_weight`（前五大权重）和 `concentration`（集中度）。规则按有效期和启用状态选取；触发事件保存观测值、阈值和证据快照，管理员或业务员可处理为确认、解决或忽略。

## 7. 版本和数据可见性

估值版本状态包括：`received`（已接收）、`parsing`（解析中）、`validating`（校验中）、`publishable`（可发布）、`pending_review`（待复核）、`published`（已发布）、`superseded`（已替代）、`rejected`（已驳回）、`failed`（失败）、`duplicate`（重复）、`non_valuation`（非估值表）和 `revoked`（已作废）。

看板和导出只读取活动产品的已发布版本。一个产品同一估值日只能有一个已发布版本；发布新版本会将该产品该日期的旧已发布版本置为已替代。已发布、已替代和已作废版本及其标准化明细不可就地修改。

导入批次中的干净版本会自动发布；一个批次按受影响产品各创建一个覆盖本批次自动发布估值日范围的 `process_analysis_run`（分析运行任务），避免历史导入为每个文件创建任务。警告版本仍需人工确认发布，单版本发布、撤回和恢复会创建分析任务。worker（后台任务进程）完成后将产品指标、公司指标和风险事件落库；分析结果携带 `analysis_run_id`（分析运行编号）。看板中的 `ready`（就绪）、`pending`（等待）和 `stale`（过期）用于区分分析结果是否覆盖当前已发布版本。

## 8. 明确暂不提供

以下不是隐藏的半成品，而是当前有意不提供的能力：

- Windows 客户端安装包和离线模式；当前只有网页版，未来可以用 Tauri（桌面应用封装）薄壳复用网页；
- 统一字段来源查询和产品详情直达原始文件；当前只能从导入批次受控下载原始文件；
- 版本历史、版本差异和复杂复核详情；
- 产品级资产配置、份额每日数据和产品级独立回撤的页面 JSON 查询（公司级回撤序列已由 `dashboard/series` 提供）；当前保留对应导出接口；
- 重新解析、重新校验、批量重试全部、已知例外、映射试跑和风险规则试算；
- 交易记录 `.xlsx` 的业务解析；它们在历史目录盘点中被识别为非估值表；
- 外部行情、交易、申赎、合同、监管和组织系统接入。
- 历史迁移命令支持清单生成、预演和正式上传；正式上传使用从登录会话取得的 `fund_session` Cookie（浏览器会话凭据），会话失效后需重新注入 `MIGRATION_TOKEN`（迁移会话值）。
