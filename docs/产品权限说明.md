# 账号产品范围

管理员进入「账号管理」，在新增业务员、普通看板用户或老板时选择「可见产品」。默认是「全部产品」，包含以后新增的产品；切换为「指定产品」后可搜索并多选。创建后点击账号行「可见产品」栏的「修改」可调整范围，填写原因后保存。管理员始终可访问全部产品，无需配置。

业务员和看板用户沿用原有页面布局与操作方式。指定产品范围的账号将「公司总览」显示为「选定产品总览」，指标、图表、列表和导出按授权产品汇总；页面不增加权限说明区。全部产品账号仍显示「公司总览」。

旧账号升级后继续保留全部产品。选择指定产品但不选任何产品时，账号可以登录，产品列表为空。停用产品的授权可以保留，但其数据不会计入已发布的活动产品总览。删除产品会清除关联授权，不会把账号变为全部产品模式。

| 能力 | 指定产品的普通用户 | 指定产品的业务员 |
| --- | --- | --- |
| 产品列表、详情、净值、风险读取和 CSV 导出 | 仅授权产品 | 仅授权产品 |
| 产品总览的规模、收益、回撤及覆盖数量 | 仅以授权且活动的产品计算 | 仅以授权且活动的产品计算 |
| 导入、复核、发布、驳回、撤回、恢复、风险处理 | 不开放 | 仅授权产品 |
| 修改产品资料、别名、份额、启用和停用 | 不开放 | 仅授权产品 |
| 新建产品、邮件同步及附件、全局科目映射、全局风险规则、全局运维和审计 | 不开放 | 不开放 |
| 账号权限和系统管理 | 不开放 | 不开放 |

全部产品账号保留原有角色能力。指定产品业务员批量发布时，仅处理授权范围内的可发布版本。

## 老板与账号权限一览

管理员新增账号或修改角色时可选择「老板」。老板沿用普通看板的业务页面及自身产品授权规则，并增加「账号权限一览」和修改其他账号可见产品的能力。普通看板已有的全局风险规则配置能力也沿用：全部产品的老板可配置，指定产品的老板不可配置。

老板通过侧栏「账号权限一览」查看账号名、显示名称、角色、状态、可见产品和最后登录时间，支持搜索、角色筛选、分页与刷新。老板视角只显示启用账号，并隐藏账号名为 `admin`、`boss`、`operator` 的三个测试账号；列表、搜索、筛选及分页总数均采用同一范围，即使请求停用状态也不会返回停用账号。测试账号按账号名精确匹配，其他同角色的启用账号正常显示。管理员查看此页及「账号管理」时仍可看到全部账号，并保留状态筛选和重新启用操作；重新启用后，非测试账号恢复在老板端显示，历史记录及产品授权保留。隐藏仅影响老板的一览展示，不删除账号，也不改变账号本身的权限。指定产品显示具体名称、代码和停用状态；未分配产品有明确说明，管理员还可通过状态列识别已禁用账号。

老板和管理员可在账号的「可见产品」栏点击「修改可见产品」，选择全部产品或指定产品，也可清空指定产品来收回全部观看权限。必须填写修改原因，保存后立即生效，并记录操作者、原因与修改前后的产品范围。修改业务员的范围时，其查看、导出及已有业务操作仍遵循同一产品授权规则。

老板可以调整其他非管理员账号（包括业务员、普通看板和其他老板），不能修改自己的范围或管理员账号；自己的范围由管理员调整，管理员固定拥有全部产品。新建、禁用、启用、改角色、重置密码、撤销会话仍仅允许管理员操作。普通看板和业务员不能读取权限一览、产品授权目录或修改任何账号授权。

即使老板自身只有指定产品权限，一览与产品选择器仍能显示完整产品名称、代码和停用状态，供为其他账号分配权限；不会因此直接获得这些产品的估值、持仓或导出权限。产品选择器包含尚未分配给任何账号的产品，分页加载全部选项。修改角色、收回产品授权或禁用账号后，下一次服务端请求立即采用新权限。

## 导入与原始文件

受限业务员上传时先校验工作簿内容能否识别为授权产品，文件名不能作为授权依据。无法确定归属、含未授权产品、依赖文件名才能识别的净值历史文件会被拒绝，可交给拥有全部产品权限的业务员或管理员处理。后台处理开始时再次校验上传人的账号和产品范围，避免排队期间权限变更后继续导入。

批次只有在所有原始文件均属于授权产品时才可访问。归属未知或混有其他产品的批次不显示，也不能下载原件或导出批次信息；新建空批次仅其创建者可见。旧版本导入的原文件没有完整工作簿识别标记，对受限账号暂不开放；其产品估值及看板数据仍可正常按授权查看。受限业务员仅可向自己创建的批次上传、完成或重试。

## 生效与缓存

保存范围后，服务端对已有会话的下一次请求直接应用新权限。前端返回窗口或定期检查账号时同步菜单和范围。产品数据需要联网读取，不再读取旧的本地业务缓存或在断网时回退到旧数据；切换账号后的旧请求不能覆盖新账号页面。静态页面资源的加载机制不变。

## 升级

需要先备份数据库并执行 `alembic upgrade head`，再启动新版后端和前端。桌面客户端也必须同步更新其内置前端，避免旧版继续读取已有业务缓存，不能只升级后端。迁移 `0012_user_fund_access` 增加账号范围、账号与产品关系，以及用于受限导入的原文件产品识别字段，旧账号自动设为 `all`。迁移 `0013_boss_role` 扩展账号角色约束，允许 `boss`，保留现有账号、会话和产品授权，不自动调整任何真实账号身份。

降级前必须明确处理所有 `selected` 账号；迁移会拒绝直接移除仍在使用的权限机制，避免降级后这些账号意外获得全部产品。本次开发不包含生产部署或真实账号授权调整。

存在老板账号时，`0013_boss_role` 会拒绝降级；需先由管理员将这些账号切换为旧版本支持的角色。后端、网页及桌面前端需同步升级，以便正确识别并显示新身份。
