## 文档与代码的责任边界

- OpenAPI（接口描述）运行结果、数据库迁移和实际代码优先于说明文字。
- `API接口说明.md` 是面向调用方的稳定说明，但不替代运行实例的 `/docs`（交互式接口文档）和 `/openapi.json`（机器可读接口描述）。
- 产品指标和风险判断只能使用估值 Excel（电子表格）能够提供或由已保存字段可靠推导的内容。外部行情、交易流水、申赎流水、合同、监管和组织系统不属于本项目数据源。
- 新增或修改路由、权限、数据字段、指标口径、状态机和保留策略时，必须在同一个提交中更新对应权威文档和测试。
- 文档中的“已实现”表示后端有真实逻辑并有测试；“前端已接入”还要求正式页面调用真实接口；“未提供”表示没有可调用的实现，不能用模拟数据替代。
- 所有示例凭据、域名密码、邮箱授权码和生产环境文件都必须使用占位符，不得写入仓库。

## 当前实现基线

- 后端：Python 3.12+、FastAPI（Python Web 框架）、SQLAlchemy（数据库访问库）、Alembic（数据库迁移工具）、PostgreSQL 16（生产数据库）。
- 前端：React（前端框架）、TypeScript（类型语言）、Ant Design（界面组件库）、Vite（构建工具）。
- 任务：数据库任务表加独立 worker（后台任务进程），不依赖 Redis（缓存/队列）或 Celery（任务框架）。
- 文件：服务端保存原始 `.xls`（旧版 Excel）和 `.xlsx`（新版 Excel）；Excel 解析、标准化、校验和分析在 worker（后台任务进程）执行，HTTP API 负责接收文件、查询结果以及执行已定义的同步和运维操作。
- 生产：Docker Compose（容器编排）运行 API、worker、PostgreSQL 和 Caddy（网页服务器）；公网入口使用 `fundscope.example.com`，内部 API 和数据库不暴露公网。
- 质量：GitHub Actions（GitHub 自动化检查）执行后端格式、类型、测试、盘点工具测试，以及前端测试、类型检查和构建。

## 文档维护规则

1. 先确认代码和运行配置，再修改文档；不能用旧草案推断现状。
2. 每次接口变化同时检查前端 API 适配器、权限矩阵、OpenAPI、测试和本文档。
3. 每次指标口径变化说明生效范围和历史数据影响；不得静默改变已发布结果的含义。
4. 过程性计划完成后从正式文档树移除；如需保留外部审计副本，应存放在代码库之外，不能被新功能引用。
5. 原始估值文件、生产数据库、Docker 数据卷和证书数据不随代码库整理操作删除。
6. 提交前运行仓库质量门禁，并检查 Markdown（轻量标记语言）链接、敏感信息和分支状态。
